## 3. 当前执行路径

```text
Reset
  → main()
  → SYSCFG_DL_init()
  → delay_cycles(CPUCLK_FREQ)
  → toggle PB22
  → repeat
```

这只是源码执行路径的静态描述，不是硬件测试结果。

## 4. 已知架构约束

- 当前不得修改 `empty.c`、`empty.syscfg`、CCS 工程、目标配置或生成文件：`CON-003`。
- 当前不得运行 SysConfig、构建、烧录、调试或硬件动作：`CON-004`。
- 引脚、电平和时序必须由正式资料及确认接线支持：`CON-005`、`CON-006`。
- 板级资源与冲突见 `docs/hardware-interface.md`，最终接口分配尚未形成。

## 6. 待定义的数据流

收到正式题面和 BOM 后，至少需要定义：

1. 原始传感器数据、单位、范围和有效性标记。
2. 校准、滤波和状态估计数据。
3. 控制目标、反馈量、误差与输出限幅。
4. 执行器命令和安全覆盖关系。
5. 日志、参数与测试数据的通道和格式。

当前不为这些数据预设类型、频率或算法。

## 8. 待定义的时序与并发模型

当前不能判断控制时序应来自：

- 主循环轮询；
- 硬件定时器中断；
- ADC/PWM/Timer 硬件触发链；
- RTOS 任务。

必须先获得控制周期、抖动容限、数据率、计算预算和故障响应要求，再通过 `DEC-*` 选择模型。

## 9. 待定义的控制与安全模型

以下内容均为 `[待确认|无]`：

- 控制对象与可测状态。
- 开环、闭环或分层控制方式。
- 控制算法、参数、限幅和抗饱和策略。
- 启动、自检、待机、运行、故障和急停状态。
- 传感器异常、超时、堵转、过流和通信故障响应。
- 调参权限、默认参数和恢复方式。

## 10. 固件实施就绪门槛

只有以下条件全部满足后，才可以规划固件或 `.syscfg` 修改：

1. 正式 `REQ-*` 及其验收指标已经建立并人工复核。
2. 实际 BOM、模块精确型号和 datasheet 已登记。
3. 最终接线达到 `[已确认|资料复核]`，并完成电源与逻辑电平检查。
4. 板级资源冲突和外设实例分配已静态审查。
5. 时序、控制和安全方案已有 accepted `DEC-*`。
6. 测试方法和安全上电步骤已定义。
7. 用户明确解除当前 docs-only 限制，并单独授权相关动作。
